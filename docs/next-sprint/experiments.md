# Proposed experiments and bounded compute plan

Status: **design recommendation, not frozen or executed**. A runnable GPU protocol
must complete instrument tests, tokenization, power simulation and manifest freeze.
This proposal does not weaken or reopen any historical gate.

## Recommendation

Make report reactivity the main experiment, with relational J-lens analysis as
its mechanistic component. Use renamed tools as a small transfer test. Defer
motivated concealment until the simpler measurement instruments work.

| Priority | Question | Payoff if successful | Main failure risk |
|---|---|---|---|
| 1 | Does reporting reveal or modify action-controlling information? | A precise limit on interpreting self-reports, plus an internal explanation | Generic extra instruction or recency explains the rescue |
| 2 | Is the J-lens missing bindings while reading the right words? | Concrete boundary between readable concepts and causal relational content | Decoder recomputes from prompt, or full residual patch only writes the answer |
| 3 | Do outcome-grounded monitors transfer across tool aliases? | Tests safety-evaluation invariance under identical transitions | Only generic tool-use competence changes; a rule-based monitor already solves the task |
| Later | Does an audience variable selectively control disclosure? | Mechanistic model of strategic reporting | Prompted roleplay or task failure masquerades as scheming |

## Experiment 1: reports as measurements and interventions

**Question.** Why do correct consequence reports improve action selection, and
what could a monitor have known before those reports existed?

Use the existing deterministic action–outcome games, but fresh concept pairs and
paraphrases. Split lexical families before inference: 48 discovery bases and 96
locked bases are an initial sizing proposal. Keep every order, target, label
permutation and frame of a base in the same split. Pilot throughput and simulate
power using whole-base effects before freezing the final sample count. The old
RBG-4 examples are development evidence, not fresh confirmation.

Start with opposed assertion/prose/redundant games plus matched opaque and
nonagentic controls. Balance the physical action, target, outcome names and
report labels. Add direct-policy controls so 'contrarian' is not a class label.
Use one neutral final action request in every primary arm:
`Choose the action that achieves the stated target. Return only A or B.`

| Arm | Prefix before the common action request | What it identifies |
|---|---|---|
| Direct | Original scenario | Unelicited baseline |
| Self-report | Two constrained consequence Q/A turns generated by this model | Total elicitation effect |
| Oracle | Same Q/A turns with correct reports | Effect with report accuracy controlled |
| Swapped | Same Q/A turns with inverted reports | Sensitivity to report content |
| Matched control | Two similarly sized non-consequence Q/A turns | Extra turns, text and task engagement |
| External facts | Same consequence information attributed to an external source | Role/source contribution; not identical-token authorship |

Repeat the oracle/swapped contrast with an explicit 'use the reports' instruction
as a secondary factor. This directly tests the extra instruction in RBG-6.
Match content and token count as closely as possible; record residual length and
position differences rather than claiming perfect matching where impossible.

**Forked diagnosis.** From the same completed scenario prefix, run a direct-action
branch and an independent report branch. Reports on the latter cannot affect the
former. Capture shared-prefix states before either query. Also capture each
branch's final pre-answer state, clearly marked as post-query. Branching here
means separate full-prefix recomputation; for this hybrid model do not assume
naive copying of a Transformer KV cache copies every recurrent state correctly.

**Primary estimand.** Within each base, average the action-accuracy difference
between self-report and matched-control arms over prespecified permutations;
then average bases equally. Use a base-level paired interval and a prespecified
paired randomization/sign-flip test under its stated exchangeability assumption.
Also report self-report minus direct. The primary comparison should demonstrate
more than extra turns; a self-minus-direct result alone is a weaker conclusion.

Report errors unconditionally and the conditional both-reports-correct subset as
a secondary, selected population. Do not filter the primary on post-treatment
report accuracy. Pre-register a minimum interesting primary gain (proposed 15
percentage points), confidence criterion and one primary test. Keep other
comparisons descriptive or apply a frozen multiplicity correction.

**Monitor comparisons.** At each declared observation point compare prompt-only
features, report text from the fork, J-lens candidate scores, a low-capacity
relational decoder, raw-residual linear probes, and output-logit baselines.
Freeze layers, features and thresholds using discovery-only grouped validation.
Report AUROC, balanced accuracy, Brier score and sensitivity at a supportable FPR,
with base-cluster uncertainty. Do not advertise 1% FPR with only tens of negatives.
Require held-out lexical and mapping transfer; include correct actions under
misleading names and incorrect actions under neutral names as hard negatives.

The full-prompt oracle already knows the correct action in this toy environment.
The monitor's target is the model's impending **error**, not the oracle label.
Once final action logits are available, they determine a forced-choice action;
no activation monitor should claim useful extra prediction over those logits.
The interesting access regime is earlier states and explanatory variable recovery,
not a fabricated deployment advantage over a trivial outcome checker.

**Stop rule.** If the fresh content-controlled effect is absent, or identical
instructions remove it, stop the mechanistic rescue claim. Report the instruction
or turn effect and retain the unspent budget. If too few failures remain for a
monitor test, report insufficient positive support instead of adapting labels.

## Experiment 2: concepts versus bindings

Treat this as a gated mechanistic component, not another broad lens atlas.
The workspace paper explicitly raises the limitation of a bag of concepts.
Both 'red' and 'blue' can appear in a readout while it fails to distinguish
`A causes red; B causes blue` from the opposite binding.

On a small discovery subcorpus, pair opposite mappings with the same vocabulary
and balanced target/output labels. First test single-token outcome concepts to
avoid unvalidated mean-subtoken proxies. Read the variable 'outcome of action A'
and the target separately. Include same-action/different-relation pairs: flip
mapping and target together so the optimal physical action stays constant. These
prevent the relation probe from being merely an action classifier.

Instrument comparisons:

- Correctly normalized J-lens candidate scores, with token forms frozen.
- A supervised low-capacity decoder over those fixed scores; label it supervised.
- A residual linear probe trained with group-held-out validation.
- Optionally a tightly budgeted relational Patchscope, validated against shuffled
  and wrong-game donors. It may recompute; its fluent text is not direct truth.

Only call a result 'formal J-space decomposition' if sparse nonnegative pursuit
is implemented and validated. A two-token span or all-token transformed residual
is a different object. Avoid spending the sprint on full-vocabulary pursuit.

**Causal test.** If a relation readout generalizes, select at most one intervention
site using discovery data and independent numerical validity. Start with a small
set of layers (e.g. 36, 40, 43) and two semantically aligned anchors, then freeze
one. A natural donor patch should change the decoded relation and the action in
the predicted direction. Full residual replacement gives an upper-bound-style
contrast; a target-word patch that only writes the final answer is insufficient.

Compare donor differences restricted to the prespecified two-concept lens span
with their orthogonal complement, norm-matched random edits, identity,
wrong-game, opposite-target and reverse patches. Call this a **selected lens-span**
experiment, not a decomposition of the whole J-space. Score relational report,
target preservation, action margin, strict repair, and distortion. Require a
counterfactual sign reversal across mappings/targets that output-token steering
cannot explain. If no selective effect beats controls, do not expand the layer
sweep on locked data.

**Interpretations.** Successful residual decoding plus failed token decoding
bounds an instrument, not the model's knowledge. Selective relational transport
would be stronger evidence about use. Report rescue without selective transport
remains a behavioral result. No positive outcome is guaranteed.

## Experiment 3: small tool-alias transfer

Build a deterministic simulator in which two tools perform fixed state changes,
including preserving versus suppressing an audit record. Cross accurate names,
opaque aliases and countersemantic names while keeping transitions, permissions,
goals and descriptions of actual effects fixed. Score the executed state change.
Use legitimate versus conflicting objectives as separately labeled conditions;
reward-maximizing suppression in a prompted game is not autonomous scheming.

A useful prospective test: freeze a monitor on one alias family, test unchanged
on new aliases, then compare its outcome sensitivity with name sensitivity.
Include identical action-token cases whose consequences differ, plus different
names whose consequences are identical. Compare against a text/tool-schema
baseline with equivalent information. No claimed white-box advantage when that
baseline or the deterministic oracle is already sufficient.

Start with a small behavioral screen; only proceed to monitor transfer if alias
changes affect behavior while consequence competence remains high. This tests a
specific evaluation confound. It does not generalize automatically to frontier
agents or real covert goal pursuit.

A historical RBG-6 successful run took 467 seconds and approximately $0.41
estimated compute, illustrating that behavior is cheap. It does not establish
throughput for a larger capture or generation experiment. The lens correction
can use archived states if accessible, avoiding a new model forward pass.

CPU locally: generation, oracle checks, tokenization, all possible report branches,
anchor offsets, statistical power simulation, probe fitting, bootstraps, plots,
artifact hashing and report generation. Modal: model loading, forward passes,
selected activation capture and actual interventions. Return/shard data promptly;
never keep an A100 attached while running CPU statistics.

Use exact checkpoint/lens revisions, a pinned image, `use_cache=False` for
full-prefix scoring, `logits_to_keep=1`, length-bucketed batches and exact BF16
state storage. Token/memory preflight determines batch size. Reserve the full
function-timeout ceiling before each paid dispatch, count failures, disable
retries, and reconcile provider charges. Memory above 32 GiB changes the rate.
