# Protocol stub: ask after the act

Status: **design stub only — not wired, not scored.** Not a live protocol ID.
Do not treat this document as blocking `rename_invariant` CPU work.

## Scientific question

Does a consequence question asked **after** the second forced press change
anything measurable about the already-taken action (measurement / disclosure),
or is the interesting intervention only the mid-trajectory ask *before*
choice2 (see `ask-mid-trajectory-protocol.md`; canonical ID
`ask_mid_trajectory`)?

| Pattern | Counts as |
|---|---|
| Ask after choice2; answers accurate; choice2 already fixed | Measurement / reveal only |
| Ask after choice2 under oversight-style framing changes the *report*, not the press | Disclosure contrast (cousin of incident-desk auditor arms) |
| Compare ask-after vs ask-before-second-act on matched scenarios | Timing-of-ask factor |

## Suggested shape (not implemented)

1. Same scenario family as mid-trajectory.
2. Forced choice #1 → optional mid control → forced choice #2 → **then**
   consequence ask (self / oracle / swapped).
3. Primary estimands on mid-answer accuracy and (if a third press exists)
   post-ask persistence — default design has **no third press**; this stub is
   report-timing, not another intervention on action.
